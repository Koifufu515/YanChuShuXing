# 候选意图确认接口与验收报告

## 结论

隔离候选版已经形成“理解问题—条件确认—安全查询—结果回看”的真实闭环。明确的单值、机构排名和趋势问题仍直接查询；歧义或缺少条件的问题只返回确认计划，不生成 SQL、不调用数据库。用户选择通过后，后端重新校验原问题、签名、字段和候选 ID，才进入原有 SQL 安全检查和只读查询链路。

本功能只位于 `YanChuShuXing_candidate_integration` 的 `candidate-integration` 分支。没有修改正式数据库内容、原 `POST /api/v1/query` 路径、三栏页面骨架、CORS 配置或 Streamlit 回退版。

## 修改清单

- API 请求增加可选 `confirmation`，响应增加可选 `confirmation`，旧请求无需改动；
- 查询管线在 SQL 生成前增加确认门，待确认响应固定 `sql=null`；
- 候选仅取自正式指标/机构只读目录，以及后端代码审核固定的分析方式和增长方式目录；自定义日期不是候选 ID，必须经过格式、顺序、范围和正式指标日期存在性校验；
- 增加确认签名和后端二次校验，拒绝伪造 token、额外字段、不存在的指标与时间选项；
- 增加已审计的“机构存款增长额排名”参数化规则，确认后仍经过原 SQL 安全检查和只读执行器；
- 中栏增加 AI 确认卡，展示原问题、理解摘要、已识别/需要确认/缺少条件/未识别四态、候选和操作；
- 确认选择、选择事件、等待确认响应和最终结果保存在原会话 `localStorage` 中，刷新和历史会话恢复后可继续；
- 最终回答和右栏明确展示最终采用的指标、分析方式、增长方式、时间和机构范围；
- 排名图在全部为正值时从 0 开始；增长结果含负值时保留负值并显示零轴。

## 接口样例

### 1. 首次提交歧义问题

```json
{
  "question": "哪家银行存款增长最好？",
  "user_id": "competition_demo_user",
  "conversation_id": "conv_001"
}
```

HTTP 400 响应的关键字段：

```json
{
  "question": "哪家银行存款增长最好？",
  "sql": null,
  "columns": [],
  "rows": [],
  "error": {
    "code": "CLARIFICATION_REQUIRED",
    "message": "请确认缺少或存在歧义的分析条件后再查询。",
    "retryable": false
  },
  "confirmation": {
    "version": "intent-confirmation-v1",
    "status": "required",
    "token": "由后端签发的确认签名",
    "fields": [
      {"key": "metric", "state": "recognized", "value": {"id": "ZB001", "label": "各项存款余额"}},
      {"key": "analysis", "state": "recognized", "value": {"id": "growth_ranking", "label": "机构增长排名"}},
      {"key": "growth_method", "state": "needs_confirmation", "options": [
        {"id": "year_start", "label": "较年初增长（以上年末为基期）"},
        {"id": "year_over_year", "label": "同比增长"},
        {"id": "month_over_month", "label": "环比增长"},
        {"id": "custom_range", "label": "自定义时间增长"}
      ]},
      {"key": "custom_start_date", "state": "missing", "input_type": "date", "visible_when": {"field": "growth_method", "equals": "custom_range"}},
      {"key": "custom_end_date", "state": "missing", "input_type": "date", "visible_when": {"field": "growth_method", "equals": "custom_range"}},
      {"key": "institution_scope", "state": "recognized", "value": {"id": "all_institutions", "label": "全部13家正式机构"}}
    ]
  }
}
```

此阶段自动化测试通过计数执行器确认数据库调用次数为 0。

### 2. 用户确认后再次调用同一接口

```json
{
  "question": "哪家银行存款增长最好？",
  "user_id": "competition_demo_user",
  "conversation_id": "conv_001",
  "confirmation": {
    "token": "首次响应返回的原 token",
    "selections": {
      "growth_method": "year_over_year"
    }
  }
}
```

成功响应为 HTTP 200，包含参数化 SQL、13 家机构真实结果、`result_type=排名`、`chart_type=bar`、`semantic.comparison=year_over_year`，以及：

```json
{
  "confirmation": {
    "status": "confirmed",
    "final_conditions": {
      "metric": {"id": "ZB001", "label": "各项存款余额", "unit": "亿元"},
      "analysis": {"id": "growth_ranking", "label": "机构增长排名"},
      "growth_method": {"id": "year_over_year", "label": "同比增长"},
      "comparison_period": {"id": "year_over_year", "label": "同比增长", "start_date": "2025-04-30", "end_date": "2026-04-30"},
      "institution_scope": {"id": "all_institutions", "label": "全部13家正式机构"}
    }
  }
}
```

较年初、同比和环比分别以正式数据最大日期为本期，计算本期年份上一年的12月31日、上年同日和上月同日作为基期；例如本期为 `2026-04-30` 时，较年初基期为 `2025-12-31`。自定义时间提交 `custom_start_date` 与 `custom_end_date`。伪造 token、提交 `ZB999`、增加未授权字段、倒置/越界日期或选择没有正式数据的日期，均返回 `INVALID_CONFIRMATION`、`sql=null`，业务查询执行次数为 0。

- 后端与前端专项测试：18 项通过；

## 已知限制

1. 当前已开放完成确认并执行的新增分析方式只有“机构增长额排名”；其他未识别分析可展示正式候选，但在对应 SQL 规则完成审核前不会执行。
2. “存款”当前使用审核别名映射到正式指标“各项存款余额”；完整近义词、错别字和复杂上下文仍需后续语义模块扩展。
3. 自定义日期已经开放，但只能选择正式数据范围内且该指标确有数据的两个日期，不支持缺失日期的自动插值。
4. 意图确认只在 Real + Rule 候选链路启用；原 LLM/Hybrid 行为保持不变，避免本次改动扩大技术路线。
5. 历史会话仍保存在当前浏览器 `localStorage`，不能跨设备或多人同步。正式目录重新发布后，旧 token 会失效，用户需要重新确认。

## 启动与回退

启动候选版：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_candidate_frontend.ps1 -GeneratorMode rule -Port 8512
```

访问 `http://127.0.0.1:8512/candidate`。当前验收服务已在 8512 运行。

回退时停止 8512 进程并启动 README 中原 Streamlit 页面即可。代码级回退基点为上一候选提交 `2280c133686fa715df4f771706295ae57aa3d1ac`；正式数据库无需恢复，因为本功能没有写入或迁移数据库。
